# Traceon · Управление требованиями и анализ влияния

[English](README.en.md)

Traceon помогает аналитику, ревьюеру и менеджеру проследить изменение от бизнес-требования до API, модели данных и тестов. Учебный проект ServiceHub содержит синтетический процесс обработки сервисных заявок.

## Запуск

```sh
docker compose up --build
```

Откройте [консоль](http://127.0.0.1:8100). Compose запускает PostgreSQL, применяет миграции и добавляет ServiceHub с исходной baseline. Учебные логины `analyst`, `reviewer`, `manager`, `admin` используют пароль `Traceon-demo-local`. Порты и пароль можно задать через локальный файл на основе [.env.example](.env.example). Пароль применяется при первом создании пользователей. Учебные настройки рассчитаны на localhost.

```sh
scripts/lab up
```

[Лаборатория](http://127.0.0.1:8101) использует отдельный проект Compose и том. `scripts/lab reset` пересоздаёт только лабораторию. `scripts/lab stop` останавливает её с сохранением данных.

## Возможности и архитектура

Проекты изолированы серверной проверкой участия. Аналитик ведёт требования, черновики, связанный граф и запросы на изменение. Ревьюер принимает решение по назначенной версии. Менеджер назначает роли и фиксирует baseline. Администратор создаёт учебные учётные записи.

Черновик сохраняется с ожидаемой revision. Отправка на согласование запечатывает содержание. Изменения утверждённой или возвращённой редакции идут в новую версию. Baseline хранит ID и значения утверждённых редакций, артефакты и активные связи. Сравнение доступно между снимками и с текущим состоянием.

Граф хранится в PostgreSQL. Тип связи определяет направление обхода, допустимость цикла и возможность продолжать путь. BFS сохраняет один детерминированный кратчайший путь до каждого найденного элемента. Отчёт хранит версию, граф, пути и ревизию графа. После изменения графа отчёт помечается устаревшим. Решения по находкам и переходы CR записываются отдельно. Матрица выводит бизнес-основания, проектные артефакты, тесты и проблемы. Знаменатель покрытия — утверждённые функциональные требования.

Модульный монолит использует Python, FastAPI, Pydantic, SQLAlchemy, Alembic и PostgreSQL. Интерфейс использует React, TypeScript, Vite, TanStack Query и React Flow. Nginx обслуживает SPA и проксирует API. Код в `backend/` и `frontend/`, тесты в `tests/`, `scripts/` и `frontend/e2e/`.

## Рабочий стол трассируемости

Выберите требование в списке проекта. Из рабочей карточки можно открыть его зависимости и анализ конкретной версии или создать связанный запрос. Реестр сохраняет фильтры и сортировку при возврате из карточки. Кнопка «CSV всего реестра» выгружает все требования проекта. В отчёте по влиянию видны направление исходной связи и направление обхода. Сравнение снимков показывает изменения по полям.

## Демонстрация

В ServiceHub откройте FR-014 и создайте запрос на обязательное подтверждение руководителем. Сравните прямой путь до API и транзитивный путь до модели данных и теста. Оцените находки, проведите согласование запроса под reviewer, создайте новую редакцию и согласуйте её. Под manager зафиксируйте новую baseline и сравните с ServiceHub 1.0. ## Границы и статус

Учебный стенд хранит синтетические данные. Права заданы на проект, администратор пользователей получает доступ к проекту через членство. Эпоха проекта консервативно помечает отчёты устаревшими даже при изменениях вне их путей. Сравнение использует полные снимки небольшого графа. Контроль качества проверяет структуру и трассируемость. Промышленная эксплуатация, SSO и внешние интеграции вне объёма. Возможные расширения — выборочный состав baseline, несколько объясняющих путей, политики хранения и групповые ревью. Отдельная публичная лицензия в репозитории не заявлена. [Статус](docs/PROJECT_STATUS.md)
