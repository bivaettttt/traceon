# Traceon · Спецификация / Specification

ServiceHub — синтетическая система обработки сервисных заявок. Изменение правил подтверждения может затронуть API, хранилище и тесты. Traceon хранит зависимости и основания для согласования, чтобы аналитик мог проверить последствия до внедрения. Корпоративные интеграции, юридические подписи и автоматическое понимание текста вне MVP.

| ID | Участник и задача | Критерий приёмки |
|---|---|---|
| FR-001 | Менеджер ведёт проекты | Участники получают явную роль в проекте. Постороннему проект скрыт |
| FR-002 | Аналитик изменяет требования | Стабильный код, версии и поле revision. Один из двух конфликтующих PATCH получает 409 |
| FR-003 | Ревьюер принимает решение | Назначенный ревьюер оценивает точный ID версии. Автор не утверждает свою версию |
| FR-004 | Аналитик связывает артефакты | Направление и тип проверяются, дубликаты и запрещённые циклы отклоняются |
| FR-005 | Аналитик оценивает влияние | Прямые и транзитивные пути воспроизводятся. Результат хранит исходную версию и ревизию графа |
| FR-006 | Команда проводит изменение | Решения по влиянию предшествуют утверждению CR. Новая редакция связана с CR |
| FR-007 | Менеджер фиксирует baseline | Снимок содержит точные утверждённые версии, артефакты и активные связи |
| FR-008 | Команда проверяет покрытие | Видны отсутствующие тесты, устаревшие привязки и неполные поля |
| FR-009 | Команда получает историю и отчёты | Аудит и фактические JSON/CSV доступны участникам |
| FR-010 | Пользователь демонстрирует ServiceHub | Изолированная среда проходит сценарий от проекта до сравнения baseline |

**Участники.** Аналитик отвечает за содержание и связи, ревьюер — за независимое решение, менеджер — за состав проекта и baseline, администратор — за учебные учётные записи.
**Термины.** Требование — стабильная сущность. Редакция — содержание в конкретный момент. Привязка — необязательный ID редакции на стороне связи. Baseline — неизменяемый состав. Путь влияния — основание для проверки аналитиком.

**UC-001.** Аналитик создаёт черновик, сохраняет с текущей revision и назначает ревьюера. Ревьюер утверждает или возвращает. Изменения после возврата заново проходят представление.
**UC-002.** Аналитик регистрирует запрос «Добавить обязательное подтверждение руководителя», выбирает редакцию, анализирует связи и сохраняет оценку. Ревьюер принимает решение. Аналитик проводит новую редакцию через согласование, проверяет тесты и закрывает запрос.
**UC-003.** Менеджер фиксирует набор утверждённых требований и сравнивает его с предыдущей baseline.
**NFR-001.** Обход детерминирован, ограничен размером проекта и завершает работу на циклах.
**NFR-002.** PostgreSQL хранит данные, аудит и снимки транзакционно. Compose и GitHub Actions воспроизводят запуск.
**NFR-003.** Права и принадлежность проверяются сервером. Сессии отзываемы, секреты не попадают в аудит.

## Матрица доступа / Access matrix

| Действие | ANALYST | REVIEWER | PROJECT_MANAGER | ADMIN |
|---|---|---|---|---|
| Список и чтение проектов | По участию | По участию | По участию | По участию |
| Создание проекта | Да | Да | Да | Да |
| Требования, артефакты, связи, CR | Да | Чтение | Да | По роли в проекте |
| Редактирование и отправка черновика | Автор | — | Автор | По роли в проекте |
| Решение по редакции | — | Назначенный | — | По роли в проекте |
| Оценка находки | Да | Да | Да | По роли в проекте |
| Решение по CR | — | Независимый | — | По роли в проекте |
| Состав проекта, baseline | — | — | Да | По роли в проекте |
| Создание учётных записей | — | — | — | Да |

## Таблица решений / Decision table

| ID | Условие | Результат |
|---|---|---|
| BRULE-001 | Субъект не участвует в проекте | 404 |
| BRULE-002 | Черновик сохранён с устаревшей revision | 409, данные первого сохранения сохранены |
| BRULE-003 | Версия на согласовании, запрос от назначенного ревьюера | Запись решения атомарна с обновлением статуса |
| BRULE-004 | Связь между проектами или pin чужой версии | Отклонение |
| BRULE-005 | Структурное ребро замыкает цикл | 409 |
| BRULE-006 | Версия pin расходится с контекстом | Ребро отмечено устаревшим, дальнейший обход остановлен |
| BRULE-007 | Есть неоценённые находки или изменился граф | Переход CR к согласованию запрещён |
| BRULE-008 | Состав baseline пуст или имя занято | 409 |
| BRULE-009 | Проект архивирован | Чтение разрешено, запись предметных данных запрещена |
