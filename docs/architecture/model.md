# Модель и архитектура / Model and architecture

FastAPI serves a modular monolith backed by PostgreSQL. React runs behind nginx on localhost. Projects scope all object identities and roles. Project writes take a project row lock, allowing deterministic conflict checks, coherent graph capture and baseline creation. This serializes project writes and keeps independent projects concurrent. Draft edits also compare a client revision.

A node identifies a requirement or an artifact. A requirement has version rows and append-only review decisions. Draft content can change until submission. A returned version is retained and its successor receives a new version number. Approved content stays sealed. The current approval is the highest approved version. Earlier approved versions are historical. Baselines embed approved versions, artifact values and links as a single immutable snapshot.

| Type | Stored direction | Impact traversal | Constraints |
|---|---|---|---|
| REFINES | requirement → requirement | forward | acyclic |
| DERIVES_FROM | requirement → requirement | reverse | acyclic with all structural edges in traversal orientation |
| DEPENDS_ON | any → any | reverse | acyclic with structural edges |
| IMPLEMENTED_BY | requirement/design → design | forward | acyclic |
| VERIFIED_BY | requirement/design → test | forward terminal | test target |
| CONSTRAINS | rule → requirement/design | forward | acyclic |
| RELATES_TO | any → any | bidirectional, one hop | allowed cycles |

BFS returns one deterministic shortest explanatory path per element. Structural traversal expands fresh edges only. Stale pinned links and associations remain visible as terminal evidence and are flagged for review. Staleness compares the pin with the current approved version, falling back to the latest version for requirements without approval. Running impact analysis captures the active graph, source version and project graph epoch. Editing affected content, creating versions, approving versions or changing links advances the epoch. Decisions persist separately per finding.

## Workflow

Requirement states: DRAFT → IN_REVIEW → APPROVED or CHANGES_REQUESTED. Both final decisions seal the reviewed content. A returned version can spawn a new draft. BASELINED and SUPERSEDED are derived historical labels.

Change requests: NEW → UNDER_ANALYSIS → IMPACT_REVIEW → APPROVED or REJECTED → IMPLEMENTED → VERIFIED → CLOSED. Analysis submission requires a current report with all item decisions. Implementation requires an approved revision tied to the request. Verification records evidence.

## Trust boundary

Opaque bearer sessions are generated by the server and stored as digests. Passwords use Argon2id. The frontend keeps session tokens in memory. Project scope is checked inside each transaction. Student data and demo credentials target local operation. Audit is an append-only database journal within the API trust boundary.
