# Traceon · Кейс для портфолио

**Бизнес-проблема.** Изменение правила подтверждения заявки затрагивает API, состояния, данные и тесты. Связи и решения теряются между документами.

**Цель и роль.** Я определил концепцию учебного продукта, демонстрационный сценарий и критерии приёмки. Анализ, проектирование, реализация и проверка выполнены с помощью Codex.

**Аналитические задачи.** Определить жизненные циклы требования и CR, матрицу прав, допустимые типы связей, модель покрытия и критерии воспроизводимого анализа.

**Модель.** Требование имеет стабильный ID и несколько редакций. Согласование хранит точную редакцию и участника. Типизированная связь может фиксировать версию конца. Baseline сохраняет утверждённый состав.

**Архитектура и алгоритм.** FastAPI и PostgreSQL хранят проекты и граф. BFS идёт по допустимым направлениям и сохраняет путь каждого результата. React Flow выделяет эти пути. Эпоха графа объясняет, почему анализ требует повторного запуска.

**Реализация и проверка.** Новый процесс ServiceHub проходит от требования до отчёта влияния, независимого согласования и сравнения baseline. Проверены конфликт правок, изоляция проектов, стабильность путей и неразрушаемость снимков.

**Границы.** Синтетические данные, локальные роли, один воспроизводимый путь на находку. [Код](https://github.com/bivaettttt/traceon) · [Требования](analysis/mvp.md) · [Результаты](testing/results.md) · [Сценарий показа](demo/interview.md)
